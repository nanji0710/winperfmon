# 设置界面行为规范（UI Settings Spec）

> 文档状态：**设计稿 v1（待确认）** · 关联：`config-schema.md`（数据契约，字段名以该文为准）
> 本文只规定**用户可见行为**：设置入口、页面划分、交互、即时生效范围、校验反馈。

## 1. 设计原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **所见即所得** | 任何改动立即反映到 Overlay / 主面板预览上，不需要「确定」按钮才生效 |
| 2 | **不阻断** | 非法输入就地提示，绝不用模态对话框拦住用户 |
| 3 | **可回滚** | 打开设置时抓一份配置快照；「取消」= 回滚快照并落盘 |
| 4 | **可拖拽优先** | 排序用拖拽 + 上下移动按钮（键盘可达），不用数字输入框排序号 |
| 5 | **宽恕缺失** | 硬件不支持的指标在列表里标注「本机不可用」而不是消失，用户能理解为什么读数空 |
| 6 | **一屏一主题** | 每页只解决一类问题，页内不嵌套滚动区域 |

## 2. 入口与窗口形态

| 入口 | 触发方式 |
|---|---|
| 主面板 | 标题栏右侧齿轮按钮 |
| 托盘 | 右键菜单「设置…」 |
| Overlay | 右键菜单（`window.clickThrough = false` 时可用）；穿透开启时通过热键 |
| 热键 | 默认 `Ctrl+Alt+F10`（可改），全局可用 |

窗口：普通可调窗口，最小 720 × 520；左侧分类导航（布局 / 指标 / 外观 / 窗口与置顶 / 采样 / 帧率 / 关于）+ 右侧内容区 + 底部固定条（`恢复默认` `取消` `应用`）。
底部条状态提示：`已保存`（防抖 500 ms 后自动落盘）／`配置只读，无法保存`／`有 3 项被修正`（点击展开诊断列表）。

## 3. 页面：布局

| 控件 | 绑定字段 | 行为 |
|---|---|---|
| 横向排布 / 纵向排布（两张大图示按钮） | `layout.orientation` | 点击立即重排；图示直观表达「一行指标」vs「一列指标」 |
| 按分组显示（CPU/GPU/风扇/帧率） | `layout.groupByCategory` | 开启后组间自动加间距 |
| 显示指标名称 | `layout.showLabels` | 关闭后只留数值+单位 |
| 显示单位 | `layout.showUnits` | — |
| 项目间距 / 分组间距（滑块） | `layout.itemGapDp` / `groupGapDp` | 0–64 Dp，拖动实时预览 |
| 横向对齐 | `layout.align` | 仅横向排布时可用（其余情况置灰） |
| 超宽换行 + 最大宽度 | `layout.wrap` / `maxWidthDp` | 开启换行后最大宽度输入框启用 |
| 无数据显示 | `layout.hideMissing` | 两选一：`隐藏该项` / `显示 N/A`（主方案默认隐藏；免驱模式下建议 N/A，便于理解为何缺数据） |

页面底部固定一块**实时预览**（按当前屏幕真实 DPI 渲染的小尺寸 Overlay 预览，宽高随内容自适应）。

## 4. 页面：指标（可见性与排序）

**左侧「可用指标」**：按分组折叠列表，每项显示名称 + 说明 tooltip（数据来源，例：`来自 Super I/O，笔记本可能不可用`）+ 本机可用性标记（可用 / 本机不可用 / 需要驱动）。

**右侧「已显示指标」**（顺序 = 展示顺序）：

| 操作 | 交互 |
|---|---|
| 新增 | 左侧双击 / 拖到右侧 / 勾选框 |
| 移除（不再展示但保留配置） | 右侧行尾「眼睛」图标（置 `visible = false`，不删除条目，便于以后恢复） |
| 排序 | 拖拽（拖动时显示插入位置线）；键盘 `Alt+↑` / `Alt+↓`；行尾上/下按钮 |
| 改名 | 双击名称就地编辑（0–24 字符，清空 = 恢复默认名） |
| 颜色覆盖 | 行尾色块 → 取色器 + 「随主题」按钮 |
| 字号倍率 | 行尾小滑块（0.5×–2.0×），实时预览 |
| 精度 | 右键菜单 0/1/2/3 位小数 |

**顶部工具条**：搜索框（按名称/ID 过滤）、`全部显示`、`全部隐藏`、`恢复默认顺序`。
**约束与提示**：

- 至少保留 1 项可见（否则最后一个「眼睛」按钮置灰并提示）。
- 横向且未换行时，预估宽度超出屏幕 → 顶部黄条提示「当前排版超出屏幕宽度，建议开启换行或隐藏 2 项（GPU 频率、CPU 频率）」，并给出「一键处理」。
- 需要 Ring0 的指标（CPU 温度/功耗、风扇）在没有驱动时标注「需要驱动」，并提供「了解如何启用」链接（指向文档，不做自动安装）。

## 5. 页面：外观（字号与颜色）

| 控件 | 绑定字段 | 行为 |
|---|---|---|
| 主题 | `colors.themeId` | 深色 / 浅色 / 自定义（选自定义后下方颜色列表启用） |
| 基准字号 | `text.baseSizeDp` | 滑块 8–48 + 数字框；旁边显示等价像素值（按当前 DPI） |
| 数值加粗 | `text.boldValue` | 开关 |
| 字号下限 | `text.minSizeDp` | 6–24，防止缩放后不可读 |
| 颜色逐项编辑 | `colors.label` / `value` / `unit` / `background` / `panelBorder` / `ok` / `warn` / `critical` / `accent` | 每行 = 名称 + 色块 + 十六进制输入框 + `取色器` + `随主题` |
| 单指标颜色覆盖 | `metrics[].color` | 在「指标」页设置，外观页只显示说明与跳转 |
| 单指标字号倍率 | `metrics[].sizeScale` | 同上 |

**可读性校验**：`value` 与 `background` 对比度 < 3:1 → 行内黄色提示「文字与背景对比度过低」；纯透明背景（alpha = 0）时给出「将使用桌面穿透」说明。

## 6. 页面：窗口与置顶

### 6.1 显示后端（决策 ④=B）

| 选项 | 行为 | 适用 |
|---|---|---|
| 自动（默认） | 真独占全屏 + RTSS 可用 → RTSS OSD；其余 → 自绘 Overlay | 绝大多数用户 |
| 仅自绘 Overlay | 永不写 RTSS，真 FSE 下不显示并提示 | 不想依赖 RTSS |
| 仅 RTSS OSD | 始终写 RTSS；检测不到时回退自绘并提示 | 已统一用 RTSS 管 OSD |

- 未检测到 RTSS 时本页显示"未检测到 RTSS"+ 官网链接/安装指引。
- RTSS 模式下"位置 / 不透明度 / 点击穿透 / 缩放"置灰并注明**由 RTSS 控制**，附"打开 RTSS 设置"按钮；字号与颜色区标注"RTSS 模式按标签近似映射，未支持的项会被忽略"。
- 首次运行向导增加可选第 4 步（可跳过）：说明"真独占全屏游戏也能看到 Overlay 需安装 RTSS"。

| 控件 | 绑定字段 | 行为 |
|---|---|---|
| 置顶策略（三选一） | `window.topmostPolicy` | `始终置顶` / `仅游戏前台时置顶` / `从不置顶`；切换立即生效（重建窗口样式，不重启） |
| 点击穿透 | `window.clickThrough` | 开启后 Overlay 不接收鼠标（防止误点）；关闭时可用右键菜单 |
| 不透明度 | `window.opacity` | 20%–100% 滑块 |
| 缩放 | `window.scale` | 50%–300% 滑块（同时放大字号与间距） |
| 位置 | `window.position.*` | 四角预设按钮 + 「自由拖拽」（提示：拖动 Overlay，按 Enter 确认、Esc 取消）+ 显示当前显示器名（`monitorId`） |
| 边距 | `window.marginDp` | 0–200 Dp |
| 独占全屏时隐藏 | `window.hideInFullscreen` | 说明文案：非注入方案在真独占全屏下无法覆盖，隐藏可避免无意义的叠层 |
| 托盘图标 / 开机自启 | `window.showTrayIcon` / `startWithWindows` | 开机自启写入 `HKCU\...\Run`，需显式开启并在「关于」页可撤销 |

## 7. 页面：采样与性能

| 控件 | 绑定字段 | 行为 |
|---|---|---|
| 传感器间隔 | `update.sensorIntervalMs` | 200–5000 ms；下方实时显示「预估额外 CPU 占用 ≈ 0.2%」之类的量测值（来自运行期统计，不是拍脑袋常数） |
| Overlay 刷新率 | `update.overlayRefreshFps` | 1–10 Hz，默认 2；提示「提高会增加游戏内开销」 |
| 主面板刷新率 | `update.panelRefreshFps` | 1–30 Hz |
| 隐藏时暂停采样 | `update.pauseWhenHidden` | 开关 |
| 电池省电 | `update.lowPowerOnBattery` | 开关 |

## 8. 页面：帧率

| 控件 | 绑定字段 | 行为 |
|---|---|---|
| 采集模式 | `fps.mode` | 自动 / 使用 PresentMon 服务 / 命令行采集 / 关闭；「自动」优先服务、失败退化命令行 |
| 目标进程 | `fps.targetProcess` | 下拉列出当前前台与近期前台进程 + 手动输入 `.exe`；空 = 自动跟随前台游戏 |
| 游戏自动开始 | `fps.autoStartOnGame` | 开关 |
| 缓冲帧数 | `fps.keepBufferFrames` | 4096–262144，显示等价时长（按当前帧率估算）与内存占用 |
| 1% Low 口径 | `fps.lowPercentile` | 0.1%–5% 单选，默认 1%；附口径说明（降序取最差 N = ceil(p × 帧数) 帧的帧时间均值取倒数） |
| 显示呈现模式 | `fps.showPresentMode` | 开关，附说明：用于自查本工具是否把游戏从 Independent Flip 降级为 Composed: Flip |

**PresentMon 缺失时的引导**：页面顶部信息条说明「未检测到 PresentMon 服务/SDK，帧率功能不可用」，给出手动安装指引与「本次忽略」；不自动下载安装。

## 9. 即时生效矩阵

| 改动字段 | 生效方式 |
|---|---|
| `layout.*`、`metrics[]`、`colors.*`、`text.*` | 仅重算布局并重绘（< 1 帧内可见） |
| `window.topmostPolicy` / `clickThrough` / `hideInFullscreen` | 重建窗口样式（`SetWindowLongPtr` + `SetWindowPos`），不重启进程 |
| `window.scale` / `position` / `marginDp` / `monitorId` | 重算几何并移动窗口 |
| `update.*` | 重设定时器周期；采样线程下一拍生效 |
| `fps.*` | 需要重开会话（停止旧采集 → 按新模式重启）；切换时 Overlay 上的帧率项短暂显示 `—` |
| `text.fontFamily` | 重建 DirectWrite 文本格式与布局缓存 |

## 10. 键盘、DPI 与可访问性

- Tab 顺序：导航 → 内容区控件 → 底部条；所有滑块可用方向键微调（`Shift` 加速 10×）。
- 全局热键（默认值，均可改）：`Ctrl+Alt+F10` 设置；`Ctrl+Alt+F11` 显示/隐藏 Overlay；`Ctrl+Alt+F12` 锁定/解锁位置（防误拖）；`Ctrl+Alt+F9` 开始/停止帧率采集。
- DPI 100%–300%：所有尺寸 Dp → 物理像素换算，字号不小于 `text.minSizeDp`；多屏混合 DPI 时按 Overlay 所在屏的 DPI 渲染。
- 颜色不作为唯一状态载体（状态色必须同时打印数值），保证色觉障碍用户可读。

## 11. 首次运行向导（3 步，可跳过）

1. **选排版**：横向 / 纵向（图示）→ 写入 `layout.orientation`。
2. **选指标**：按「CPU/GPU/风扇/帧率」分组勾选，默认勾选目录中的默认可见项 → 生成 `metrics` 顺序。
3. **选位置与置顶**：四角预设 + 置顶三态 → 写入 `window.*`。
结束后立即显示 Overlay 预览，并把配置落盘（此时才创建 `config.json`）。

## 12. 明确不做（v1 范围外）

| 项 | 原因 |
|---|---|
| 每游戏独立配置档案 | 需要新增 `profiles[]` 与切换逻辑，v2 |
| 阈值（warn/critical）自定义 | v2；v1 用指标目录内置阈值 |
| 自定义字体族选择列表 | v1 只允许系统 UI 字体 |
| 配置云同步 / 账号 | 与「不联网、不采集」原则冲突 |
| 自动下载安装 PresentMon / PawnIO | 安全与合规：只提示、不代装 |
